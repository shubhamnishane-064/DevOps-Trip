## Today's Goal
Understand how DNS turns names into IP addresses, read and query DNS records with `dig`, and debug "works by IP but not by name" problems.

## What I Did
- Learned the hierarchy: root, TLD, authoritative server and recursive resolver, and how answers are cached for the TTL.
- Learned the lookup order on Linux: cache, `/etc/hosts`, then DNS (set in `/etc/nsswitch.conf`).
- Learned the record types A, AAAA, CNAME, MX, TXT, NS, SOA, PTR.
- Practised `dig` (`+short`, `+trace`, `-x`, `@server`), `nslookup`, `host`, `getent hosts` and `resolvectl`.
- Saw that `dig` ignores `/etc/hosts`, while `ping` and `curl` use it.
- Wrote `dnscheck.sh`, which shows the main records, the status (NOERROR, NXDOMAIN, SERVFAIL) and the query time for any domain.
- Linked it to AWS: Route 53, the VPC resolver (base IP + 2) and private hosted zones.

## Lab Summary
```bash
sudo apt install dnsutils -y
dig +short google.com
dig google.com MX
dig +trace github.com | head -30
dig @8.8.8.8 github.com | grep "Query time"
echo "203.0.113.99  test.local" | sudo tee -a /etc/hosts
getent hosts test.local          # sees the hosts entry
dig +short test.local            # does not
./dnscheck.sh github.com 8.8.8.8
```
Result: queried records, compared two DNS servers, proved that `dig` ignores the hosts file, and broke and fixed `resolv.conf`. (Add a screenshot in `documentation/images/`.)

## What I Learned
- Works by IP but not by name means DNS.
- `Temporary failure in name resolution` = no usable DNS server. `Name or service not known` = the name was not found.
- Lower the TTL before changing an IP, so the change spreads fast.
- A CNAME can't be used on the bare domain.
- On Ubuntu, `/etc/resolv.conf` is usually generated by systemd-resolved, so change DNS in netplan.
